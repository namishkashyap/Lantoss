2026-10-30 - Lantoss 2.0.2: home-network security and send to phones

New PCs and phones are approved on this PC (Settings → "Ask before a new
computer or phone connects", on by default). A first pairing is confirmed on
both screens, and auto-connect only reconnects PCs that are already paired.
A new phone waits until the PC clicks Allow, or until it enters the access
code. Until then it cannot see files, folders, notes or other PCs.

The phone page is encrypted (HTTPS) with the PC's own certificate. Phones
show a certificate warning once. Plain HTTP and the .local name only
redirect to the encrypted page.

Pairing uses a commit-then-reveal comparison code, so it can't be guessed
offline. New pairings need 2.0.2 on both PCs; PCs that are already paired
keep working.

Send to a phone: the Send page lists approved phones and browsers, and
files sent to one appear only on that phone.

Shared spaces can be limited to chosen PCs.

Received files carry the Windows "downloaded" mark, and shortcut or
desktop.ini files are saved with .txt added. Approval windows warn about
programs and scripts, look-alike names and hidden characters.

Per-device limits stop one device from flooding connections, approval
prompts or notes. Disconnect and Block take effect immediately. Phones never
see local paths in error messages. Data files on macOS and Linux are
readable only by the user, and sync keeps the newest five versions. The
macOS installer checks the app's seal instead of re-signing it.

2026-10-26 - Lantoss 2.0.1: phone address and macOS install

whole bundle is sealed and ad-hoc signed while packaging (rcodesign 0.29.0,

download also includes a double-clickable "Install Lantoss.command", which
copies the app to Applications and clears the download flag.

2026-10-26 - Lantoss 2.0: people, pictures, notifications and security fixes

New macOS and Linux apps (source/Desktop, Avalonia) run the same sharing
engine with every screen of the Windows app: send, devices and browsers,
transfers, phone & browser QR, text & links, shared spaces, two-way sync,
history and settings. They also include the approval and pairing dialogs,
system notifications and a tray menu. On macOS and Linux the device key is a
PKCS#12 file readable only by the user. Packages:
- macOS: Lantoss.app for Apple Silicon and Intel (zip with install.sh)
- Linux: .deb and .tar.gz for x64 and arm64
INSTALL.md covers each platform. The previous Windows-only version stays on
the release/1.x branch and the v1.9.0 release.

Phones and PCs connected through the web page now appear in Devices and Home.
Each shows its name, picture, device type, address and last activity, and can
be disconnected. Visitors choose a name and picture on the page. The picture is
cropped and re-encoded to a 128 px JPEG, and the server accepts only small
PNG/JPEG data. The PC owner can set a profile picture in Settings, shown in the
sidebar and on the page. Lantoss shows a Windows notification as soon as a PC
or browser asks to send files, and clicking it opens the app. The approval
window, Transfers, History and notes now show the sender's name, device type
and address. An optional setting saves received files in Inbox\<sender>.
The design is refreshed: deeper ink, a stronger emerald accent, bold
headings, rounder controls and a solid active sidebar item, in the app and on
the page.

Security fixes:
- Code-protected direct pairing now needs on-screen confirmation on both PCs,
  so an access code relayed through a spoofed advert cannot pair silently.
- .local names only redirect to the PC's IP address, so a device that takes
  over the name cannot reach the portal's cookies or API.
- The elevated firewall script escapes curly single quotes in the app path.
- One IP address can hold at most four browser sessions.
- Expanded 8.3 short names (FLOWSH~1) are validated, so they cannot reach the
  reserved .flowshare- folders.
