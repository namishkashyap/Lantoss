# 2026-10-30: Lantoss 2.0.2, home-network security, send to phones, screenshots

Owner's request:
- Fix the home-network items of the security review ([plan](2026-10-30-security-review-and-hardening-plan.md)).
- Make the app as secure as possible while keeping it easy to use on a home network or LAN.
- Let the PC send files directly to a chosen phone.
- Save screenshots of every section in `previews/` for a design hand-off.

Out of scope (another day):
- Trusted devices ([feature plan](2026-10-30-trusted-devices-and-admin-server-plan.md))
- The admin server
- Online access (security Part B)

Numbers in brackets refer to the security plan.

## Items

- [x] 1. **Approve new devices (on by default) [0.1, 0.2].**
  - New setting "Ask before a new computer or phone connects", on by default, so existing installs are protected too.
  - PCs:
    - The first pairing always needs confirmation on both screens.
    - Auto-connect only reconnects PCs that are already paired.
  - Phones:
    - A new browser waits until the PC clicks **Allow**, from the Phone & browser or Devices page, or until it enters the access code.
    - Files, spaces, notes and the device list stay hidden until then.
  - Turning the setting off restores the 2.0.1 behaviour, for fully trusted networks.
- [x] 2. **Encrypted phone page [0.3].**
  - HTTPS with the PC's own certificate, on by default, with a Settings switch.
  - The QR code and links use `https://`. The old `http://` address and `.local` names redirect to it.
  - The session cookie is `Secure` with the `__Host-` prefix.
  - The PC shows the certificate fingerprint.
  - No HSTS: with a self-made certificate, HSTS would turn the one-time browser warning into a hard block.
- [x] 3. **Who can open each shared space [0.4].**
  - Each space can allow either all paired PCs or only the PCs ticked in the list, in both apps.
  - Existing spaces keep "all paired PCs".
  - Phones still need approval (item 1).
- [x] 4. **No hidden-character names [0.5].**
  - File, PC and device names refuse Unicode format characters, such as direction overrides and zero-width characters.
  - Approval windows show a short key fingerprint, and warn when the name matches another device.
- [x] 5. **Received files are marked and risky files are defused [0.6].**
  - Windows `Zone.Identifier` marks every file received from a phone or PC.
  - Shell-control files (`desktop.ini`, `.url`, `.lnk`, `.scf`, `.library-ms`, `.searchConnector-ms`) are saved with `.txt` added, so they stay inert. Sync skips them.
  - Approval windows warn when a batch contains programs or scripts.
- [x] 6. **Flood and lock-out protection [0.7].**
  - Per-address limits on:
    - phone-page connections
    - phone-page streams
    - pending offers
    - TLS connections, with a shorter wait before sign-in
  - A 30-second cooldown after three declined offers within two minutes, and a timer that clears expired offers. One decline never locks a phone out.
  - Notes quota per device, and notes written on the PC are never evicted. Peer text posts are rate-limited.
  - The login limiter is per address, with no global lockout. The least recently used session is evicted instead of refusing new ones.
  - Stale discovery entries are evicted.
- [x] 7. **Stores and memory can't be filled up [0.8].**
  - The peer limit is checked before saving, and unverified records are evicted first.
  - Finished jobs and old history are released from memory.
  - Sync backups keep the newest 5 per file.
  - Forced rescans need a sync grant and run at most every 30 seconds per PC. Per-file hashing is bounded by the per-address connection limits rather than a separate rate limit.
  - Stores are re-validated when they load.
- [x] 8. **Disconnect and block are immediate [0.9].**
  - Disconnecting a phone also cancels its downloads.
  - **Block** keeps that address out until Lantoss restarts.
- [x] 9. **No internal details sent out [0.10].**
  - Phones get generic error messages, with no local paths or user names.
  - A peer's error text is shown as quoted text from the other PC, cleaned and shortened.
- [x] 10. **Fake PCs and .local names [0.11].**
  - The PC never gives up its local name permanently.
  - The phone's "Other PCs" list shows paired PCs only.
  - The code screen shows the PC's address and fingerprint.
- [x] 11. **Safer "Open link" [0.12].**
  - Opens only the parsed http/https address.
  - Asks first and shows the host. Warns on links to LAN names.
- [x] 12. **Private data files on macOS and Linux [0.13].**
  - Data folder 0700 and files 0600, with existing files fixed at startup.
  - The key file is created fresh.
  - A single-instance lock per data folder.
- [x] 13. **Small hardening [0.14].**
  - Constant-time CSRF check.
  - `Permissions-Policy`, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy` headers, plus Trusted Types.
  - Profile pictures over 1024 px are refused.
  - The pipe name includes the session ID, with back-off.
- [x] 14. **Stronger pairing comparison [0.15].**
  - Each side commits to its random value before seeing the other's, so the comparison code can't be ground offline.
  - New pairings need 2.0.2 on both PCs; PCs that are already paired keep working.
- [ ] 15. **TLS 1.3 [0.16].** Partly done: the expiry warning is in. TLS 1.3 is not; see Not done.
  - TLS 1.3 is offered first, which encrypts certificates between 2.0.2 PCs. TLS 1.2 stays for 2.0.1 peers.
  - A warning appears 30 days before the device certificate expires.
- [x] 16. **Release and build hardening [0.26 interim, 0.27, 0.29].** The Explorer DLL keeps only the ASLR/DEP linker flags; see Not done.
  - The macOS `install.sh` verifies the shipped seal instead of re-signing. It re-signs only if the user confirms.
  - The Explorer certificate uses a password from an environment variable and timestamped signatures.
  - **Settings → Remove Explorer menu trust** removes the machine-wide trust.
  - Locked NuGet restore with `packages.lock.json`, and a NuGet vulnerability audit.
  - Cached build tools are re-verified.
  - The Explorer DLL is built with hardening flags.
- [x] 17. **Send to a phone (new feature).**
  - The Send page lists connected phones and browsers next to PCs.
  - Choosing one offers the files to that phone only. Other phones don't see them.
  - The phone shows "<PC> sent you N files" with download buttons.
  - Works in both apps.
- [x] 18. **Security tests [0.30].** `SecurityTests.cs` covers each item above.
- [x] 19. **Screenshots for design.**
  - `previews/` holds:
    - every page in both themes for Windows
    - every page for macOS/Linux
    - the phone page at phone size
  - `previews/README.md` lists each screen.
- [x] 20. **Release 2.0.2.**
  - Version bump, CHANGELOG entry and INSTALL.md updates (HTTPS warning, Allow step).
  - Installers, PR and release.

## Not done

- **TLS 1.3 between PCs.** Bouncy Castle needs RSA-PSS signing and a TLS 1.3 certificate request in the custom signer. Getting that wrong would break every PC-to-PC connection, and it can't be checked against older peers here. It moves to the online work (security Part B).
- **Stack-protector and _FORTIFY_SOURCE for the Explorer DLL.** On MinGW these can add a `libssp-0.dll` dependency that Explorer can't load, and g++ isn't installed here to check. Only `--dynamicbase`, `--nxcompat` and `--high-entropy-va` were added.
- **Never run on a real device:**
  - the macOS `install.sh` seal check
  - signtool timestamping
  - the elevated "Remove Explorer menu trust" button
  - phones accepting the certificate warning (only headless Chrome was used)

## Not in this change

- Signed releases and moving the admin-only steps out of a user-writable folder [0.26, 0.28]. Both need a paid code-signing certificate (decision 5 is open).
- A rotating discovery ID and certificate renewal through the old key [0.16]. These need protocol work that is shared with the online design.
