# 2026-11-03: hopo 2.3.0, trusted devices, in-app approvals and two separate apps

Owner's request:
- A phone has to be approved every time it connects. Add a way to allow a device permanently (a trusted device).
- Files from a trusted device should arrive without an accept prompt.
- Approving a waiting device should happen on Home, in a floating in-app card at the bottom right ("Waiting for approval"), not in a separate window or a menu page. The Phone panel above the dock should also let you allow it.
- Make the admin and user two different apps, not one app with modes.

This change covers Windows only.

## Items

- [ ] 1. **Trusted phones and browsers.**
  - "Always allow" approves a waiting or connected phone and remembers it.
  - The phone receives a long-lived random trust cookie (HttpOnly, 1 year). Only its SHA-256 hash is saved, in `Preferences.TrustedBrowsers` (at most 64 entries).
  - A phone that presents a trusted cookie is approved straight away, even after hopo restarts or the access code is turned on. Its uploads are accepted into the default folder without a prompt.
  - Trusted phones are listed in Devices (admin), where they can be removed. Removing one also stops trusting any of its connected sessions.
- [ ] 2. **Trusted PCs.**
  - Devices (admin) has "Trust" and "Stop trusting" for a paired PC (`Peer.Trusted`).
  - Files from a trusted PC are accepted into the usual inbox without the accept prompt, and the PC is labelled "Trusted".
- [ ] 3. **Floating approvals on Home.** When a phone or browser is waiting, a card appears at the bottom right of Home, inside the app.
  - It reads "Waiting for approval" and shows the device name, address and buttons.
  - The admin app offers Allow, Always allow and Block. The user app offers Allow only.
  - It disappears when nothing is waiting.
  - The Windows notification now points to Home.
- [ ] 4. **Approvals in the Phone panel.**
  - The Phone panel above the dock lists waiting devices with the same buttons.
  - In the admin app it lists connected phones that are not trusted yet, with Always allow.
- [ ] 5. **Two separate apps.**
  - `Lantoss.exe` is "hopo", the user app. It also opens Explorer shares, the tray and autostart.
  - `hopoAdmin.exe` is "hopo Admin", the admin app. It is the same code published under its own name, with its own window title, taskbar identity and Start menu entry. It asks for the admin PIN when it opens (or asks you to create one), and closes if you cancel.
  - The in-window mode switch is removed. The menu footer now has "Open hopo Admin" in the user app, and "Open hopo" and "Change PIN" in the admin app.
  - Both apps use the same data, so one runs at a time. Opening one while the other is open hands over: the open app closes, asking first if a transfer is running, and the new one starts. If the PIN is cancelled after a handover, hopo (user) starts again.
  - `Lantoss.exe --admin` stays as a developer shortcut to the admin app.
  - The admin app keeps the Explorer menu and autostart pointing at `Lantoss.exe`.
- [ ] 6. **Build and installer.**
  - `build.ps1 -Mode Publish` also publishes `hopoAdmin.exe`.
  - The MSI installs it, and the "hopo Admin" shortcut targets it.
  - The installer checks expect it.
- [ ] 7. **Checks.**
  - A browser test: after Always allow, a fresh browser carrying only the trust cookie connects without approval, and its upload needs no prompt.
  - UI regression keeps passing with the new menu footer.
- [ ] 8. **Verify and release 2.3.0.**
  - Tests, UI regression and format check.
  - Rebuild the seven setup files and publish v2.3.0.
  - Open a PR and merge it (the owner has given permission).

## Notes

- The phone page now uses HTTP by default, so anyone watching the same Wi-Fi could copy a trust cookie. Trust only phones on your own home network. With HTTPS on (Settings), the cookie is encrypted in transit.
