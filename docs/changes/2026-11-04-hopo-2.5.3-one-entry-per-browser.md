# 2026-11-04: hopo 2.5.3, one entry per phone browser

Owner's report: after opening the phone link in Chrome on an iPad, Home showed "iPad · Chrome" in three places. Each new page session (a reopened tab, another page address, a lost cookie) was listed as its own device, and stayed for 12 hours.

## Items

- [x] 1. **One entry per browser.** BrowserPortal.Browsers lists each browser once: sessions from the same address and browser (for example "iPad · Chrome") show as one, the approved and most recently seen one. Home's rings, the Send to choices, the Devices page and the macOS/Linux app use it. The approval lists still show every waiting session.
- [x] 2. **Clear stale copies.** When a browser starts a new session, its earlier sessions from the same address and browser that have not been seen for 2 minutes are ended. Open tabs check in every few seconds, so they are kept.
- [x] 3. **Disconnect ends every copy.** Disconnecting a browser ends all its sessions from that address and browser, so a hidden copy cannot reappear.
- [x] 4. **Release 2.5.3.** Bump the version, build both Windows setups and the six macOS/Linux packages, merge, tag v2.5.3 and publish the GitHub release.

## Verification

- New checks in Feature20Tests: four sessions from one address and browser show as one device, and Disconnect ends all four. build.ps1 -Mode Test: 285 passed, 1 skipped. CheckFormat clean. The macOS/Linux app builds.
- Both setups pass verify-installer (2.5.3, 12 files); all six macOS/Linux packages pass.
- Not checked on a real iPad.
