# 2026-10-26: Lantoss 2.0.0

The new version is developed in the same repository on `release/2.0.0` and ships as `v2.0.0`.
Only the items below are in scope.

## Items

- [x] 1. **Browser devices in the device list.**
  - Devices has a "Connected through the web" section and Home lists active browsers.
  - Each entry shows name, picture, device type (from the User-Agent), IP address, connection time and last activity.
  - **Disconnect** ends the session and cancels its pending uploads.
- [x] 2. **User naming.**
  - Visitors set "Your name" on the web page. It is stored in that browser and sent again after reconnecting.
  - Names are limited to 40 characters, with no control or bidi/format characters.
  - The PC's own name is labelled "Name shown to other devices" in Settings.
- [x] 3. **Profile picture.**
  - Settings → Profile picture (Choose/Remove) center-crops the image to 128 px and re-encodes it as PNG, or JPEG if needed, up to 64 KB.
  - The picture is shown in the sidebar and on the web page header (`/api/picture`).
  - Visitors' pictures are cropped to a 128 px JPEG in the browser. The server accepts only PNG/JPEG data up to 64 KB.
  - Without a picture, a bold initials avatar is shown.
- [x] 4. **Windows notification for incoming files.**
  - A notification appears as soon as a PC or browser asks to send, before the approval window opens. It shows "<sender> wants to send you files", the file count, size and address.
  - Clicking it opens Lantoss.
  - The same Settings toggle controls it, renamed to "Show Windows notifications for incoming and finished transfers".
- [x] 5. **Sender details for tracking.**
  - The approval window shows the sender's picture, name, device type, address and request time.
  - Transfers, History and the CSV export record "Name (device · browser)" instead of "Phone / browser". History rows read "From/To <sender> · <address>".
  - Browser notes carry the visitor's label.
- [x] 6. **Sender folders.** The optional Settings → Transfers setting saves inbox files into `Inbox\<sender>\`. The folder name is sanitized, and reserved or empty names fall back to "Unknown sender". Shared-space uploads keep their fixed folder.
- [x] 7. **Security review.** All five confirmed findings are fixed (table below).
- [x] 8. **Professional UI refresh.**
  - Palette: deeper ink and a stronger emerald accent in Light, and a deeper background with a brighter mint in Dark.
  - Typography and shape: bold weights for headings and primary buttons, and rounder buttons, inputs and cards.
  - Navigation: the active sidebar item is a solid accent bar with white text.
  - People: avatars on device rows and in the sidebar, and the trust badge no longer stretches.
  - The web page gets the same palette, heavier headings, a profile card and the host picture.
- [x] 9. **Version 2.0.0.** App 2.0.0, MSI definition and installer scripts 2.0.0, and a CHANGELOG entry. Built, tested and published `app\Lantoss.exe` 2.0.0.0.

## Security findings and fixes

| Severity | Finding | Fix |
|---|---|---|
| Medium | An access code typed into a spoofed "PC" advert could be relayed to the real PC, which then paired silently (`pair-direct` trusted the code alone). | When a code is required, direct pairing also needs on-screen comparison approval on both PCs, and the pairing is recorded as key-verified. Normal no-code direct connection is unchanged. |
| Medium | Any LAN device can claim `share-wollvo.local`. After a takeover and handback, the attacker's script was same-origin with the real portal and could use the phone's session. | `.local` names now only redirect `/` to the PC's IP address. The page, cookies and API are served only on the IP origin. |
| Medium | The elevated firewall script escaped only `'`. PowerShell also ends single-quoted strings at U+2018–U+201B, so a crafted folder name could inject commands. | All four curly-quote forms are doubled as well. |
| Low | 64 cookieless requests filled the browser session table for 12 hours. | One IP address can hold at most 4 sessions, and a new one replaces that address's oldest. |
| Low | 8.3 short names (`FLOWSH~1`) expanded by `GetFullPath` bypassed the reserved `.flowshare-` filter. | `FileCatalog.Within` also validates the expanded segments. |

## Verification

- `.\source\build.ps1 -Mode Test`: 245 checks passed, 1 skipped (the same symbolic-link privilege skip as the 1.9 baseline of 235). The 10 new checks cover pairing confirmation, names, pictures, sender folders, device labels, firewall quoting, the browser device list, disconnect and the per-IP session cap.
- `-Mode CheckFormat`: passed. `-Mode Publish`: `app\Lantoss.exe` 2.0.0.0.
- `Lantoss.exe --ui-regression` with fresh data: 25 WPF checks passed. `--ui-smoke`: 20 Light/Dark page renders reviewed.
- `node source/tests/browser-ui.test.cjs`: 16 browser DOM checks passed.

## Not verified / notes

- The `.local` redirect has no automated test, because the loopback test portal does not claim a local name. Real phones, two-PC Wi-Fi and the Windows notification popup were not tested on physical devices.
- The MSI was not rebuilt, because this PC has no w64devkit g++ or Windows SDK tools. The Explorer DLL and identity package are unchanged and stay at 1.9.0.0.
- PCs still show initials for other PCs, because exchanging pictures between PCs needs a protocol change (out of scope).
- Repeated preview runs reuse `work\lantoss\preview-state`, which makes the "one Open link" UI check fail on the second run. Use `--data-dir` with a fresh folder.

## Out of scope

- Exchanging profile pictures between PCs.
- Trusted auto-accept, drag-and-drop to a device, pause/resume (offered, not chosen).
- Updating the screenshots in `previews/`.
