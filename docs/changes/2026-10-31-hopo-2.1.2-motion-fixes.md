# 2026-10-31: hopo 2.1.2, motion fixes, calmer rings and the design's background

Owner's feedback on 2.1.1 (Windows):
- An error, "Cannot animate the 'X' property on 'System.Windows.Media.TranslateTransform' because the object is sealed or frozen", appears around closing the menu and changing the theme.
- The motion is not smooth.
- On Home, the wave rings react too fast to the pointer. They should be thinner, and there should be fewer of them.
- The background lines are missing, so the window looks empty and flat, and the light theme lacks colour.
- The top bar's pill shapes render as ovals. They should be rounded rectangles, including the badge beside the logo.
- Show links without "https://".

## Items

- [x] 1. **Theme-switch crash.** WPF freezes a brush once it is placed in the window's resources, so the animated glass edge and sheen brushes could not be animated after a theme change. Start their animations before adding them to the resources.
- [x] 2. **Smoother motion on Windows.**
  - Drop the per-frame blur on the ring glow layer.
  - Paint the two background glows with radial gradients instead of opacity masks.
  - Use cheaper shadows on the dock, the dock panels and the menu.
  - Cache the dock panel and the menu as bitmaps while they animate in. (Done differently: the dock panel no longer animates a 3 px blur as it opens, which was the costly part. Bitmap caching would still redraw every frame while the rows inside fade in.)
- [x] 3. **Calmer wave rings.**
  - Use 7 of the design's 12 rings.
  - Make the lines thinner: a 0.5 px line with a soft 1.6 px halo.
  - Slow the spin by 1.5× and the shape change by 1.6×.
  - Ease the pointer's slow-down and swell in over about half a second, so moving the mouse never makes the rings jump.
- [x] 4. **Background from the design.**
  - Faint concentric rings every 64 px around the centre of the window. They fade in from 340 px and out by 1050 px.
  - Window-sized purple and green glows (125% × 135% of the window, as in the design), with stronger colour in the light theme.
- [x] 5. **Rounded rectangles.** The LOCAL badge beside the logo, the network chip in the top bar and the page badges use rounded corners instead of the oval that WPF draws for an oversized corner radius.
- [x] 6. **Links without https://.** Phone page addresses are shown as `192.168.1.12:48588`. The QR code, Copy link and Open page still use the full address.
- [x] 7. **macOS/Linux app.** Items 3–6 in Avalonia.
- [x] 8. **Verify and release 2.1.2.**
  - Tests, UI regression and format check.
  - Rebuild the seven setup files and publish release v2.1.2.

## Verification

- The crash was reproduced outside the app: a brush added to the window's resources comes back frozen, and animating it afterwards throws the same error. Starting the animation first keeps it unfrozen.
- `build.ps1 -Mode Test`: 279 checks passed, 1 skipped (symlink privilege). `-Mode CheckFormat` passed. Both apps build with 0 warnings.
- Windows `--ui-regression`: 27 passed. Home and Settings renders in both themes show the background rings, the glows, the seven rings and the rounded chips.
- `verify-installer.ps1` passed (hopo 2.1.2, 19 files, 3 shortcuts). All six macOS/Linux packages passed `verify.cjs` and tar.exe, and the Mac bundles are sealed.
- The MSI was built from `work\msi-stage`, because the owner's running copy holds `app\Lantoss.exe`.

## Differences

- macOS/Linux:
  - There is no LOCAL badge in the top bar, so there was nothing to round.
  - The glows are one window-sized radial brush with the same geometry instead of two ellipses.
  - Home's own outer rings were removed, because the shell now draws the background rings on every page.
- Typed links without https:// rely on the browser trying HTTPS first. Chrome, Edge and Safari do this. The QR code keeps the full address.
