# 2026-11-03: hopo 2.5.0, phone and browser page from the design

Owner's request: build the web screens from the Claude Design canvas ("Web — desktop browser" and "Web — phone") as the new phone and browser page, for both hopo Users and hopo Admin. Both apps serve the same page.

## Items

- [x] 1. **Desktop browser layout** (Web.dc.html).
  - The header has the hopo mark, a "Connected to <PC>" chip and a round profile button.
  - The profile button opens a popover with name, picture and an Appearance switch (System, Light, Dark).
  - The main column has "Share with <PC>" and tabs: Send to PC, Get from PC, Text & links (with count), Folders (with count).
  - The side column has the PC card (radar ripples, name, address, encryption chip), the other-PCs list and "Good to know".
- [x] 2. **Panels.**
  - Send: a dashed picker. Once files are chosen it switches to the list, with a file count and size, Add more and Clear. Send to PC is at the bottom right. Live transfers sits underneath.
  - Get: the shared-file list, or a "Nothing shared yet" empty state with "Check again".
  - Text: the note field and Share button side by side, and rows with Copy and Open.
  - Folders: rows for the shared folders, plus the folder browser with Upload here.
- [x] 3. **Phone layout** (WebPhone.dc.html, under 720 px wide).
  - A compact PC strip replaces the radar card.
  - Each tab has its own heading.
  - The tabs become a bottom bar with Send, Get, Text and Folders.
  - Buttons are 48 px tall.
- [x] 4. **Look.** Use the design's glass, buttons, chips, tabs, rows, drifting glows and motion, with reduced-motion support and the light theme kept.
  - No coloured sheen line: the owner removed it in the app, and only the white edge sweep stays.
  - The page uses local fonts only, with no Google Fonts. It stays offline and inside the page's security policy.
- [x] 5. **Keep behaviour.** Same element ids and server API. Waiting for Allow and the access-code form still show in the main column. Update the browser UI test for the new Appearance switch.
- [x] 6. **Verify and release 2.5.0.**
  - Run the tests, the browser UI test and the format check, and render the page in headless Chrome at desktop and phone widths.
  - Build both setups and the macOS/Linux packages, then open the PR, merge it and publish the release.

## Verification

- `build.ps1 -Mode Test`: 283 checks passed, 1 skipped. `browser-ui.test.cjs`: 16 passed. The Appearance checks now press the System, Light and Dark buttons. `-Mode CheckFormat` passed.
- Headless Chrome, driven over DevTools against the test page server, captured every tab, an open folder, the profile popover and the "waiting for Allow" state. These ran at 1440 px and 390 px, in dark and light. The page has no sideways scroll at 390 px.
- `verify-installer.ps1 -App Users` and `-App Admin` passed: 74.4 MB each, 12 files, 3 shortcuts. Both exes are 80.6 MB. All six macOS/Linux packages passed.

## Differences from the design

- Sample names in the design (Family PC, NK) are replaced by the real PC name and the visitor's initials or picture.
- The PC card shows the address the page was opened on. Its chip reads "Encrypted · approved by the PC" only over HTTPS. Otherwise it is neutral and reads "Not encrypted · approved by the PC".
- "Good to know" also carries the encryption line, the old page footer's "Local sharing · private to your Wi-Fi" line, and the "waiting for Allow" text, which now names the Home card and the Phone panel.
- Folders gain Upload here, which opens Send with that folder as the destination. The "Upload to …" label appears only then.
