# 2026-11-03: hopo 2.5.0, phone and browser page from the design

Owner's request: build the web screens from the Claude Design canvas ("Web — desktop browser" and "Web — phone") as the new phone and browser page, for both hopo Users and hopo Admin. Both apps serve the same page.

## Items

- [ ] 1. **Desktop browser layout** (Web.dc.html).
  - The header has the hopo mark, a "Connected to <PC>" chip and a round profile button.
  - The profile button opens a popover with name, picture and an Appearance switch (System, Light, Dark).
  - The main column has "Share with <PC>" and tabs: Send to PC, Get from PC, Text & links (with count), Folders (with count).
  - The side column has the PC card (radar ripples, name, address, encryption chip), the other-PCs list and "Good to know".
- [ ] 2. **Panels.**
  - Send: a dashed picker. Once files are chosen it switches to the list, with a file count and size, Add more and Clear. Send to PC is at the bottom right. Live transfers sits underneath.
  - Get: the shared-file list, or a "Nothing shared yet" empty state with "Check again".
  - Text: the note field and Share button side by side, and rows with Copy and Open.
  - Folders: rows for the shared folders, plus the folder browser with Upload here.
- [ ] 3. **Phone layout** (WebPhone.dc.html, under 720 px wide).
  - A compact PC strip replaces the radar card.
  - Each tab has its own heading.
  - The tabs become a bottom bar with Send, Get, Text and Folders.
  - Buttons are 48 px tall.
- [ ] 4. **Look.** Use the design's glass, buttons, chips, tabs, rows, drifting glows and motion, with reduced-motion support and the light theme kept.
  - No coloured sheen line: the owner removed it in the app, and only the white edge sweep stays.
  - The page uses local fonts only, with no Google Fonts. It stays offline and inside the page's security policy.
- [ ] 5. **Keep behaviour.** Same element ids and server API. Waiting for Allow and the access-code form still show in the main column. Update the browser UI test for the new Appearance switch.
- [ ] 6. **Verify and release 2.5.0.**
  - Run the tests, the browser UI test and the format check, and render the page in headless Chrome at desktop and phone widths.
  - Build both setups and the macOS/Linux packages, then open the PR, merge it and publish the release.
